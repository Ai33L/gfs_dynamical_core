# `gfs_dynamical_core.jax` — technical manual

A comprehensive manual for the **differentiable JAX dynamical core** and the
Held–Suarez model built on it, plus runnable examples of the capabilities a JAX
core unlocks that a conventional Fortran core cannot offer (gradients, Jacobians,
ensembles, variational optimisation, singular vectors).

## 📖 The manual

**[`manual.pdf`](manual.pdf)** (source [`manual.tex`](manual.tex)) — read this
first. Contents:

- **Part I — the core:** architecture and data flow; conventions (float64/CPU,
  bottom-to-top levels, GL grid, reality symmetry); the state containers; the
  spherical-harmonic transforms (scalar + spin-weighted, precompute kernels,
  triangular truncation); the primitive-equation dynamics; and the IMEX-RK
  semi-implicit stepper.
- **Part II — building & running a model:** `_model.build_model`, the Held–Suarez
  forcing, and time integration with `lax.scan`.
- **Part III — differentiable modelling:** what the gradient *is* and *with
  respect to what*; reverse (adjoint) vs forward (tangent-linear) mode; the
  adjoint-for-free argument vs hand-coded Fortran TLM/ADM; the six capabilities
  below; and the numerical caveats (chaos, checkpointing memory, complex spectral
  fields, the forward-mode tracer-limiter pitfall).
- API quick reference + further reading.

## 🛠️ Developer's guide

**[`DEVELOPER_GUIDE.md`](DEVELOPER_GUIDE.md)** — the complement to the manual,
focused on the **code itself**: repository map, module dependency graph, the
call graph of one time step, the pytree/traced-vs-static design, invariants you
must not break, the `jit`/`grad`/`vmap` tracing contract, extension points
(physics, spectral injection, tracers, transform swaps), the climt wrapper,
testing, and a conventions/gotchas cheat-sheet. Read this before modifying the
core.

## ▶️ Runnable examples

In [`examples/`](examples/). Each runs at **T21 in a few minutes on a laptop CPU**.
Run from the repository root:

```bash
python -m docs.gfs_jax_manual.examples.ex01_run_forward        # jit + lax.scan forward run
python -m docs.gfs_jax_manual.examples.ex02_ensemble_vmap      # ensemble via jax.vmap
python -m docs.gfs_jax_manual.examples.ex03_gradient_sensitivity  # adjoint sensitivity (jax.grad)
python -m docs.gfs_jax_manual.examples.ex04_jacobian           # Jacobian (jacfwd / jacrev)
python -m docs.gfs_jax_manual.examples.ex05_optimize_ic        # fit an IC (4D-Var flavour)
python -m docs.gfs_jax_manual.examples.ex06_singular_vector    # optimal perturbation (jvp + vjp)
```

| script | capability | Fortran equivalent |
|--------|------------|--------------------|
| `ex01_run_forward.py` | compile the whole time loop once, integrate | ordinary run |
| `ex02_ensemble_vmap.py` | ensemble as a batch axis | many executables |
| `ex03_gradient_sensitivity.py` | ∂(metric)/∂(initial state) | hand-coded **adjoint model** |
| `ex04_jacobian.py` | full Jacobian, forward & reverse | hand-coded **tangent-linear model** |
| `ex05_optimize_ic.py` | fit IC/params to a target by gradient descent | **4D-Var** infrastructure |
| `ex06_singular_vector.py` | fastest-growing perturbation (power iteration on MᵀM) | TLM+ADM + eigensolver |

`_model.py` is the self-contained model builder the examples share (a good
reference for "how to assemble a model from the core primitives").

**Prerequisite:** float64 + CPU are pinned automatically at the top of each script
(`JAX_ENABLE_X64=True`, `JAX_PLATFORMS=cpu`). The examples import
`gfs_dynamical_core.jax` (installed) and `climt` (for setup-time constants).
